GUIDE DU PROJET — back_engineering_foot2
=========================================
Etat au 16 octobre 2026.

Le projet fait deux choses :
  A. un PIPELINE DE DONNEES : WhoScored + FotMob -> CSV enrichis + dashboard PNG (18 graphiques) ;
  B. un PORTRAIT 3D du match (page web Three.js) construit a partir de ces CSV, et sa video.

2. COMMENT FAIRE TOURNER
------------------------
2.1 Un match, de bout en bout :
      python postmatchdashboard_whoscored_v2.py                     (ids en haut du fichier)
      python -m pmd.run --fotmob <id> --whoscored <id> --out data/<Match> --cache data/<Match>/raw
        -> <Domicile>_vs_<Exterieur>_qualifiers_expanded.csv, _momentum.csv, _match_info.csv, _general.json, _Dashboard.png
2.2 Les calendriers (url + date de tous les matchs, journees 0 a 40) :
      python -m pmd.fixtures                                        (les 6 competitions, saison en cours)
      python -m pmd.fixtures --leagues ligue-1 laliga --season 2025/2026 --rounds 0 40
2.2b Les ids WhoScored (fichier exporte de la page des matchs WhoScored) :
      python -m pmd.whoscored_fixtures data/fixtures/sources/*.csv     (plusieurs exports fusionnes, sans doublons)
        -> data/fixtures/whoscored_fixtures.csv : id WhoScored, date yyyy-mm-dd, equipes, championnat, saison, score,
           id FotMob du meme match (les deux ids dont pmd.run a besoin)
      Les fichiers sources ont ete obtenus avec l'extension Instant Data Scraper sur les pages des tournois WhoScored
      (ex. https://www.whoscored.com/regions/250/tournaments/12/europe-champions-league). Pour les autres saisons, mieux :
      python -m pmd.whoscored_schedule --season 2025/2026 [--leagues laliga ...] : ids WhoScored de toute une saison
      (soccerdata, ~3 min par championnat) relies automatiquement a FotMob ; teste sur LaLiga 2025/2026 : 380/380.
      Ligue des champions non geree par soccerdata : garder l'export manuel pour elle.
2.3 Tests : python tests/test_pipeline.py   et   python tests/test_export.py
2.4 Verifier les donnees : python tools/validate_events.py <csv> --momentum <momentum.csv> [--fotmob <json>]
2.5 La 3D : python tools/build_data.py <csv> [--home "Nom"]  puis  node tools/check_engine.js
      page : python tools/serve.py  puis  http://localhost:8000/fabric/   (?demoCards=1 pour voir les cartons)
2.6 La video : node tools/render.js --fps 60 --out out/frames --scale 1  puis  tools/encode.sh out/frames out/video.mp4 60
2.7 Sur Colab : tools/make_colab_zip.sh, puis ouvrir notebooks/run_on_colab.ipynb dans Colab et suivre les cellules
      (envoyer dist/pmd_colab.zip, installer, lancer le test hors ligne, choisir les ids, lancer, telecharger).


3. CE QUI A ETE FAIT — DONNEES (pipeline / export)
--------------------------------------------------
- Les qualifiers WhoScored sont eclates en colonnes (valeur, ou True pour un drapeau) ; PassEndX/Y passes en metres.
- Zones : zone 1-18 (6 bandes x 3 couloirs, zone 1 a gauche devant son but), zone de phase (Build / Progress /
  Penetrate / Finish, 26,25 m chacune), couloir (Wide / Half Space / Central, gauche / droite), pour le depart (x,y),
  l'arrivee (endX,endY) et la destination de passe (PassEndX,Y).
- Distance (x,y) -> (endX,endY) ; conduite de balle avant chaque passe (point de reception, distance, gain vers l'avant).
- xT des passes et des conduites et momentum par minute, avec ta formule (AKapich), coquille end_y corrigee.
- Identifiant FotMob de chaque joueur (photo : https://images.fotmob.com/image_resources/playerimages/<id>.png) et
  fichier d'informations du match (equipes, logos, couleurs clair/sombre, date, competition, genre, stade, affluence).
- Explication des ids satisfiedEventsTypes (docs/satisfiedEventsTypes_explained.txt).
- Regles de verification des donnees pour d'autres matchs (tools/validate_events.py) : elles ont trouve les 8 fautes
  "offensives" (la faute est commise par l'equipe qui a le ballon).


4. CE QUI A ETE FAIT — LA 3D (detail complet dans docs/REGLES_3D.txt)
---------------------------------------------------------------------
- Territoire : la ligne bleu/blanc suit les actions du CSV (90 % des actions du bon cote de la ligne), lentement
  (l'horloge du match ralentit la ou il faut, video ~282 s), une seule direction a la fois, lissage des pointes.
- Percees : une partie de la ligne court vers chaque tir, but, corner (au-dela du point) et chaque faute (sur le point) ;
  langue etroite pour les contre-attaques. Verifie : 45/45 tirs-buts-corners, 22/22 fautes.
- Fautes : flash, percee, puis toute la ligne revient calmement a plat sur la ligne de la faute ; le jeu repart de la.
- Buts : pas de recul de l'equipe qui marque juste avant ; inondation de couleur ; carte du buteur ; engagement a plat
  sur la ligne mediane pendant ~2 s avec un eclair "KICK-OFF". Penalty : terrain noir et vague depuis le point.
- Relief : seuls les buts sont hauts ; occasions, corners, coups francs, avancees restent bas (14 m max) et sont plus
  LARGES quand l'xG / l'xT est grand ; aucune colline ne reste dans le terrain de l'autre equipe.
- Mi-temps : la camera fait un demi-tour, les equipes attaquent dans l'autre sens ensuite.
- Interface : pause (clic / espace), pas de bouton son, barre de momentum cliquable pour revenir en arriere ou avancer,
  remplacements "entrant / sortant", cartons (icone + animation : pulsation rouge, pluie pour le jaune), etiquettes
  d'occasion "joueur · issue · xG".
- Pour d'autres matchs : equipe a domicile detectee, codes et drapeaux, minutes de 2e mi-temps, buts contre son camp,
  verifications automatiques (tools/check_engine.js).


5. LA REORGANISATION DU CODE (pmd/)
-----------------------------------
- L'ancien script (2 554 lignes, 302 instructions globales) est decoupe en modules ; plus d'identifiants de match dans
  le code ; ce qui depend de Colab (envoi des fichiers au navigateur) est isole dans run.download().
- Les 16 filtres de tirs recopies du dashboard sont remplaces par une seule fonction.
- Preuve que rien n'a change : sur les memes donnees brutes, le nouveau code produit EXACTEMENT les memes fichiers que
  l'ancien, octet par octet, image du dashboard comprise ; tests/test_pipeline.py le reverifie a chaque fois, hors ligne.
- Limite honnete : dans dashboard.py, le code de dessin des 18 graphiques est garde tel quel (isole, pas reecrit
  graphique par graphique) pour garantir la meme image.

INSTALLATION ET SERVEUR (17/10/2026)
- ./setup.sh : cree .venv (requirements.txt), installe les paquets Node et Chrome for Testing 131, verifie ffmpeg.
  ./setup.sh --system installe aussi les paquets systeme (Linux : apt-get ; Mac : Homebrew), --check lance les
  10 regles du moteur sur France-Angleterre.
- Ensuite : .venv/bin/python -m pmd.make3d --fotmob <id>.
- Serveur : Dockerfile (docker build --platform linux/amd64 -t match-fabric . puis docker run ... --fotmob <id>),
  ou ./setup.sh --system sur un Debian / Ubuntu. Sans carte graphique, la 3D est rendue en logiciel (SwiftShader),
  meme image qu'avec le GPU du Mac. tools/browser.js trouve Chrome tout seul (ou variable CHROME).
